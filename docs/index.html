Explain this prediction

What POST /explain returns: each sensor's impact in cycles (its readings swapped for a healthy engine's, then re-predicted), plus a note for the maintenance manager. With Ollama running, a local LLM writes the note; without it, the template below is used.

All models compared

Selected on cross-validation RMSE (5 folds, grouped by engine). Test numbers were logged for every run but never used to choose.

How it's built

Everything runs locally with one command. No paid APIs.

Load

NASA C-MAPSS FD001: 100 run-to-failure engines, 21 sensors, checksum-verified download.

Features

Model

Linear baseline vs a gradient boosting grid, GroupKFold by engine, every run tracked in MLflow.

Explain

Per-sensor what-if impacts in cycles, written up by a local LLM via Ollama with a template fallback.

Serve

FastAPI: /predict, /explain, /model/info. Pytest suite, Docker image, ready for the maintenance copilot.

Data
A. Saxena and K. Goebel (2008). Turbofan Engine Degradation Simulation Data Set, NASA Prognostics Data Repository, NASA Ames Research Center. Subset FD001 (one operating condition, one fault mode).
RUL
Remaining useful life: operating cycles left before failure. Training labels capped at cycles.
RMSE
Root mean squared error of predicted RUL at each test engine's last recorded cycle, in cycles.
NASA score
PHM08 scoring function summed over the 100 test engines. Lower is better; late predictions cost more than early ones.
